
## Admin API Specification

All endpoints are relative to the base URL `/api/v1/admin` and require an authorized admin role

### 1. Admin Management

| Method | Endpoint | Description | Key Payload / Query |
| --- | --- | --- | --- |
| GET | `/admins` | List all system administrators | `page`, `limit` |
| POST | `/admins` | Create a new admin | `name`, `email`, `password` |
| GET | `/admins/{id}` | Retrieve admin details | None |
| PUT | `/admins/{id}` | Update admin credentials or status | `name`, `email`, `is_active` |
| DELETE | `/admins/{id}` | Remove or deactivate an admin | None |

### 2. Coach Management

| Method | Endpoint | Description | Key Payload / Query |
| --- | --- | --- | --- |
| GET | `/coaches` | List all coaches | `page`, `limit` |
| POST | `/coaches` | Add a new coach | `identifier`, `seat_count`, `is_reserved` |
| GET | `/coaches/{id}` | Retrieve coach details | None |
| PUT | `/coaches/{id}` | Update coach configuration | `identifier`, `seat_count`, `is_reserved` |
| DELETE | `/coaches/{id}` | Remove a coach from the system | None |

### 3. Station Management

| Method | Endpoint | Description | Key Payload / Query |
| --- | --- | --- | --- |
| GET | `/stations` | List all available stations | `page`, `limit` |
| POST | `/stations` | Add a new station | `name`, `code`, `location` |
| GET | `/stations/{id}` | Retrieve station details | None |
| PUT | `/stations/{id}` | Update station details | `name`, `code`, `location` |
| DELETE | `/stations/{id}` | Remove a station | None |

### 4. Line Management

| Method | Endpoint | Description | Key Payload / Query |
| --- | --- | --- | --- |
| GET | `/lines` | List all train lines | `page`, `limit` |
| POST | `/lines` | Add a new route/line | `name`, `start_station_id`, `end_station_id`, `stations` (ordered array) |
| GET | `/lines/{id}` | Retrieve line configuration | None |
| PUT | `/lines/{id}` | Update route and intermediaries | `stations` (ordered array of IDs and distances) |
| DELETE | `/lines/{id}` | Delete a line | None |

### 5. Schedule Management (Date & Session)

| Method | Endpoint | Description | Key Payload / Query |
| --- | --- | --- | --- |
| GET | `/schedules` | List upcoming train sessions | `date_from`, `date_to`, `line_id` |
| POST | `/schedules` | Schedule a train session | `line_id`, `departure_time`, `coach_ids` (array) |
| GET | `/schedules/{id}` | Retrieve session details | None |
| PUT | `/schedules/{id}` | Modify session time or coaches | `departure_time`, `coach_ids` |
| DELETE | `/schedules/{id}` | Cancel a scheduled session | None |

### 6. Additional Operations: Analytics & Reporting

Referencing the file Assignment - LSF SE Interview 2026.pdf, the following operations support the recommended administrative views:

* Administrators need visibility into occupancy rates across different route segments.


* The system should provide a view of the revenue generated by the segment-based pricing model.


* Data must be dynamically retrieved since the number of coaches and stations are treated as configurable.



| Method | Endpoint | Description | Key Payload / Query |
| --- | --- | --- | --- |
| GET | `/reports/occupancy` | Generate seat occupancy reports | `schedule_id`, `segment_id` |
| GET | `/reports/revenue` | Generate financial performance reports | `date_from`, `date_to`, `line_id` |
